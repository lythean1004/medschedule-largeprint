# 약 먹는 시간표

**약봉투의 작은 글씨를, 가족이 확인한 큰 글씨 시간표로.**

[서비스 사용하기](https://medschedule-largeprint.vercel.app/) · [사용 방법](#사용-방법) · [스킬의 서비스화](#스킬의-서비스화) · [검증 상태](#검증-상태)

MABC 2026 결선 · **11번 박도현** · 대표 스킬 `medicine-schedule-largeprint`

사진 한 장에서 약별 초안을 만들고, 보호자가 원본과 대조·수정한 뒤 큰 글씨 카드로 정리하는 웹서비스입니다. 확인한 결과를 PNG·텍스트·인쇄물로 전달할 수 있습니다. 회원가입과 앱 설치는 필요하지 않습니다.

> 상단 배너는 개념을 설명하는 일러스트입니다. 실제 동작 화면과 시연 검증 자료는 결선 제출 PDF·데모 자료에서 확인할 수 있습니다.

## 가족의 불편에서 시작했습니다

오랜 질환으로 약을 드시는 아버지와 장인어른은 작은 글씨를 읽기 어렵고, 휴대폰 사용에도 익숙하지 않았습니다. 가족에게 전화로 약봉투 내용을 묻는 경험에서 출발했습니다. 어머니와 장모님의 큰 글씨에 대한 반응을 보며 결과를 쉽게 읽고 전달하는 방향으로 다듬었습니다.

MVP에서는 **보호자가 확인을 담당하고, 어르신이 확인된 결과를 이용합니다.** 가족 경험은 제작자의 정성 관찰입니다. 복약 오류 감소나 시간 절감의 효과를 측정한 실험 결과는 아직 없습니다.

## 사용 방법

1. [공개 서비스](https://medschedule-largeprint.vercel.app/)에서 개인정보를 가린 약봉투 사진 한 장을 선택합니다.
2. 글씨·방향·잘림을 확인하고 필요한 경우 회전한 뒤 **‘이 사진으로 읽기’**를 누릅니다. 사진 선택만으로 분석을 요청하지 않습니다.
3. 약별 초안을 원본과 대조합니다. **약 이름, 1회 먹는 양, 복용 횟수, 조건, 며칠분, 시간대**를 확인하고 잘못 읽거나 빠진 내용은 수정합니다.
4. 시간대는 원본 또는 약사에게 확인한 내용으로 선택합니다. **‘1일 2회’라는 횟수만으로 아침·저녁을 임의로 정하지 않습니다.**
5. 약별 확인과 전체 확인을 마치면 **‘큰 글씨 시간표 보기’**로 결과를 엽니다.
6. 확인한 결과를 화면에서 보고, 필요에 따라 이미지 저장·텍스트 공유·복사·인쇄를 이용합니다.

복용 조건은 선택 입력입니다. 별도로 입력하지 않은 조건은 결과에 포함되지 않으며 화면에서 이를 안내합니다. 원본이 불명확하면 임의로 채우지 말고 약사에게 확인해 주세요.

## 주요 기능

| 기능 | 현재 동작 |
|---|---|
| 사진 준비 | 저장 사진 선택·카메라 요청, 확대·회전, 명시적 분석 버튼 |
| 약별 초안 | OCR 텍스트를 약명·1회량·횟수·조건·기간과 원문 근거로 구조화 |
| 보호자 확인 | 원본과 나란히 대조·수정, 약별·전체 확인, 수정 시 확인 해제 |
| 큰 글씨 결과 | 아침·점심·저녁·그 외 네 카드. 그 외에서 자기 전·필요시·비매일 약 구분 |
| 결과 재사용 | 현재 카드 PNG, 전체 시간표 PNG, 텍스트 공유·복사, 브라우저 인쇄 |
| 선택적 확인 일정 | 사용자가 기간·시각을 정해 ICS 파일 다운로드. 캘린더에서 직접 가져오기 |

ICS 파일에는 약 이름·용량·개인정보를 넣지 않습니다. 약별 복용 종료일을 계산하거나 복용 완료를 기록하는 기능은 아닙니다. 기기에 가져온 뒤 일정과 알림 설정을 직접 확인해야 하며, 시간표를 수정해도 이미 가져온 일정은 자동으로 바뀌지 않습니다. A4 한 장 출력도 보장하지 않습니다.

## 스킬의 서비스화

대표 스킬은 약봉투·조제 안내의 필요한 내용을 추려 쉬운 한국어 시간표로 정리하는 `medicine-schedule-largeprint`입니다. Timely와 Solar Pro 4로 시작한 스킬의 규칙을 웹서비스의 추출 프롬프트, 검토 화면, 결과 표시 로직으로 옮겼습니다. 웹이 Timely 스킬 객체를 직접 호출하는 구조는 아닙니다.

| 초기 기획 | 최종 MVP에서 반영한 변화 |
|---|---|
| 사진을 읽고 시간표로 정리 | Document OCR과 Solar Pro 4의 역할을 분리하고 약별 JSON 초안 생성 |
| 업로드 후 바로 출력 | 사진 확인, 명시적 분석, 원본 대조, 약별·전체 확인 단계 추가 |
| 시간대별 네 칸 | 큰 글씨 카드, 수정·재확인, 그 외 복용 유형 구분 |
| 화면·인쇄 중심 | PNG와 텍스트 전달, 선택적 ICS 확인 일정으로 재사용 확대 |

스킬의 핵심 기준은 **원문에 없는 정보 추정 금지, 근거 제시, 미확인 상태 표시, 보호자 대조**입니다. 프롬프트 지시만으로 이 기준을 완전히 달성한 것은 아닙니다. 현재 자동 추출의 의미 오류와 개선 과제는 아래에 공개합니다.

## 서비스 구조

```text
브라우저: 사진 준비와 명시적 분석 요청
    ↓ POST /api/schedule
Vercel 함수: Upstage Document OCR → Solar Pro 4 → JSON 구조 검사
    ↓ 약별 초안과 원문 근거
브라우저: 원본 대조·수정 → 사용자 확인 → 큰 글씨 카드·저장
```

| 구성 | 역할 |
|---|---|
| `index.html` | HTML/CSS/JavaScript 화면, 사진 준비, 검토·확인, 결과·PNG·ICS 생성 |
| `api/schedule.js` | OCR 요청, Solar Pro 4 구조화 요청, 결과 스키마 검사 |
| `solar-pro4` | OCR로 얻은 글에서 약별 필드·근거·미확인 사항 추출 |
| Vercel | 정적 페이지와 서버 함수 호스팅 |

실제 서버 요청 경로는 `extractMedicationDraft`를 사용합니다. 빈 약 목록, 미완료·잘못된 JSON과 필드 오류를 처리합니다. JSON 구조 검사는 의료적 의미의 정확성 검사와 다릅니다. 여러 사진·여러 처방을 한 번에 합치지 않으며, PDF 입력은 웹 MVP의 지원 범위로 보장하지 않습니다.

## 검증 상태

**2026-09-14, 기능 기준 커밋 `09e1aad`의 공개 배포 서비스에서 확인했습니다.**

| 확인 항목 | 관찰 결과 |
|---|---|
| 공개 접속·배포 연결 | 공개 URL 응답과 GitHub Public 상태 확인. Production 배포가 기능 기준 커밋을 가리키며 공개 HTML과 저장소 HTML의 해시 일치 |
| 실제 안내문 사진 2건 | 각각 5개 약 초안 반환. 약 목록 생성 성공을 정확도 100%로 해석하지 않음 |
| 추출 오류 | 제품 함량을 1회량으로 읽거나, 인쇄된 복용 조건 선택지를 실제 조건으로 읽는 사례 관찰 |
| 원본 대조 후 결과 | 한 사례의 1회량·기간과 확인된 시간대를 반영한 뒤 큰 글씨 결과 및 전체 PNG 다운로드 확인 |
| 미검증 | 다양한 봉투의 반복 정확도, 어르신 독립 사용성, 기기별 인쇄·공유와 ICS 가져오기, 임상·정량 효과 |

다음 우선순위는 **함량과 1회량의 구분, 인쇄 선택지 해석, 수정값과 추출 근거의 구별**입니다. 그 뒤 실제 사용자 동의하에 전사 오류, 확인 완료 시간과 도움 없이 수행한 단계를 측정할 계획입니다. GitHub 커밋 이력은 개발 변경 기록이며 사용자 실험 횟수를 뜻하지 않습니다.

## 제공 범위와 개인정보

- 약봉투에 적힌 내용을 대조해 크게 정리합니다. 효능·부작용·병용 판단, 복용 방법 변경, 복용 종료일 계산은 제공하지 않습니다. 불명확한 내용은 약사에게 확인해야 합니다.
- API 키는 서버 환경변수 `SOLAR_PRO_API_KEY`에 둡니다. 브라우저나 저장소에 실제 키를 넣지 않습니다.
- 앱 자체 DB·파일 저장소·브라우저 영구 저장소에 사진과 결과를 저장하는 기능은 없습니다. **사진은 서버·OCR로, 추출 글은 Solar로 전송됩니다.** 외부 서비스의 로그·보관 정책은 별도입니다.
- 업로드 전 자동 개인정보 가림은 구현하지 않았습니다. 사용자가 먼저 가려야 합니다. 프롬프트의 개인정보 제외 지시도 완전한 제거를 보장하지 않습니다.
- 저장한 PNG·인쇄물·공유 텍스트는 사용자 기기나 선택한 앱에 남습니다. 사용자의 대조와 범위 제한만으로 의학적 정확성 또는 법적 적합성을 보장하지 않습니다.
